今天花了一个小时，做了一个小工具，并在 GitHub 上留下了两个仓库：带图形界面的 [zotero-cleaner-gui](https://github.com/Tenktau/zotero-cleaner-gui) 和纯命令行的 [zotero-cleaner-cli](https://github.com/Tenktau/zotero-cleaner-cli)。一句话概括它做的事：把下载文件夹里那些“其实 Zotero 早就有了”的重复 PDF 找出来，安全地送进回收站。

这件事让我对“和 LLM 一起写代码”有了一点新的体会，顺手记录一下。

## 痛点

我的 Zotero 资料库这些年攒下了不少附件，而我的「下载」文件夹是一个无情的收件箱：论文随手下载，归档进 Zotero 之后，下载文件夹里那份永远留在原地。

更麻烦的是，Zotero 入库时会自动给文件改名（`作者_年份_标题.pdf`），而下载文件夹里那份还叫 `paper_v3_final_FINAL(2).pdf`——按文件名比对，根本认不出它们是同一篇论文。

于是文件夹越滚越大，硬盘一点一点被侵蚀，而你永远没有动力去清理，因为根本不知道哪些能删。这是典型的“知道该清理，但永远不想动手”。

## 一个小时，两个工具

于是中午我坐下来，打开对话框，说了句：“帮我写个工具：找出下载文件夹里和 Zotero 附件内容重复的 PDF，移进回收站，要安全。”

这一个小时大致是这样分配的：

1. **理清需求**——“重复”指**内容**重复，用 SHA-256 指纹判定，改名、加 `(1)` 后缀统统不认；
2. **划清边界**——只动目标文件夹，Zotero 库本体一根手指头都不碰；删除走回收站（可恢复），绝不永久删除；目标目录若恰是 Zotero 附件目录或其子目录，直接拒绝执行；
3. **填掉现实里的坑**——兼容 Zotero 自定义数据目录（要读 `prefs.js`）、OneDrive 重定向的下载文件夹（要用 `SHGetKnownFolderPath`）；
4. **让模型去写代码**。

第 4 步，才是这“一小时”里真正的魔法时刻。

先是命令行版本，PowerShell 写的，`-DryRun` 先预览、删除前再确认一次。写完一看——可这工具的潜在用户，未必人人都乐意开终端。于是又把同一份核心逻辑用 C# WinForms 包了个界面：单个 `.exe`，绿色便携，双击即用。最后连发布都自动化了——推一个 `v*` 标签，GitHub Actions 自动编译、打包、发布 Release。

时间线可以给个参考：CLI 版本 12:15 提交，GUI 版本 12:21 提交，12:27 修掉 CI 里的一个坑，12:44 补完 README。从坐下到两个仓库就绪，前后差不多就是一个小时。

## 它怎么工作

原理一句话能讲完，但每个细节都是冲着“安全”去的：

1. 给 Zotero 附件目录里每个 PDF 算 SHA-256，建一张 `大小 → 哈希 → 附件路径` 的索引表；
2. 扫描下载文件夹时先比**文件大小**——大小都不一样，内容必然不同，直接跳过哈希，省掉大目录里绝大部分 IO；
3. 大小能对上的才做哈希比对，命中即判定为重复；
4. 删除走 Windows 回收站而非永久删除（GUI 用 `SHFileOperation` 的 `FOF_ALLOWUNDO`，CLI 用 .NET 的 `SendToRecycleBin`），误删也能捞回来。

![去重流程](./assets/img/zotero-cleaner-flow.png)

顺带一提，整个 GUI 程序编译出来只有 **20KB 出头**——没有引用任何第三方库，界面是 WinForms 手写的。编译直接调用 Windows 自带的 .NET Framework 里的 `csc.exe`，**连 SDK 都不用装**，`build.cmd` 双击即得 `.exe`，CI 里的 Windows runner 同样如此。

## 感受

把这一个小时摊开看，真正花在“敲代码”上的时间很少。大部分精力在前 3 步——把需求想清楚、把边界划明白、把真实世界各种畸形输入说清楚。而恰恰是前 3 步的质量，决定了代码是“一遍过”还是“反复返工”。

这大概是和 LLM 协作最反直觉的一点：**瓶颈从来不在打字，而在“说清楚”**。模型负责把你那点“低熵”的意图，膨胀成几百行细节密布的样板代码——WinForms 布局、P/Invoke 签名、哈希管道、CI 的 YAML。这些活以前也得从搜索引擎里拼凑，现在只是拼得快了。

但安全边界和最终验证，还是得自己来。回收站、只动目标目录、拒绝清理 Zotero 库本体——这些不变量是我一句话一句话钉进需求里的；写完还得真跑一遍，确认回收站里确实躺着想删的文件。

所以我一直很认可一个说法，就是“大语言模型时代，人人都是产品经理”。

下次我打算更进一步：让模型先反过来问我十个问题，把需求逼得比我自己想得还清楚——说不定那一小时还能再砍一半。
